# Calibration

How precise is each rule of the default set on real Magento code? This page is generated by `bin/calibration/report` from the graded samples in [`calibration/graded/`](https://github.com/SilinMykola/magento-perf-check/tree/main/docs/calibration/graded/); do not edit it by hand.

## Corpus

Defined in [`calibration/corpus.json`](https://github.com/SilinMykola/magento-perf-check/blob/main/docs/calibration/corpus.json), with versions and archive checksums:

- Magento 2.4.9 core (`vendor/magento`)
- 25 most-downloaded `magento2-module` packages from Packagist that install on that version (`app/code` of the corpus copy)
- Not included: Mage-OS. composer create-project mage-os/project-community-edition from https://repo.mage-os.org/ hung three times on 2026-10-23/24 on stalled downloads (no CPU use, no file written for 10 minutes), also with COMPOSER_MAX_PARALLEL_HTTP=4 and with a GitHub token. The owner decided to calibrate without it; Mage-OS is a fork of the same core.

Test code is excluded (the tool's default), and so are `*-sample-data` modules at sampling time.

## Method

1. Every default rule ran on the corpus. Up to 30 findings per rule were drawn with a fixed seed (20261023, `bin/calibration/sample`).
2. Each sampled finding was graded by reading the code around it:
   - `TP`: the rule's claim holds;
   - `TP-low`: it holds, but the impact is negligible;
   - `FP`: the claim does not hold;
   - `unclear`.
3. Each finding was graded once, by a single grader. The "Owner re-checked" column shows how many verdicts the owner reviewed and how many of those were changed; the owner decided on 2026-10-24 not to re-check this round.
4. Precision = (TP + TP-low) / (TP + TP-low + FP): how often the rule is right. `unclear` findings are excluded.
5. Impact share = TP / (TP + TP-low): how often a correct finding matters.
6. Thresholds (SPEC section 7):
   - `error` stays at ≥ 90 % precision, becomes `warning` at 75–90 %, and moves to experimental below;
   - `warning` stays at ≥ 75 % precision and moves to experimental below;
   - a rule that stays in the default set with an impact share below 50 % goes one more step down: `error` to `warning`, `warning` to `info`;
   - with fewer than 10 graded findings, the rule keeps its severity and is marked "insufficient data".

## Limitations

- With up to 30 findings per rule, precision has a wide margin of error. Read it together with the counts, not as an exact figure.
- Only reported findings are judged. Missed findings (recall) are not measured.
- `TP-low` is a judgement about impact without measuring time or memory.
- Every verdict comes from one grader, without a second review. A grader who knows the rules' logic may lean towards their claims.
- The corpus is open-source code. Project code may use patterns the corpus does not contain.
