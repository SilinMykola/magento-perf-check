# T-01: `getLayout()->createBlock()` in a template

| | |
|---|---|
| Severity | `warning` |
| Status | default set |
| Analyzer | PHPStan on `.phtml` files, identifier `magentoPerf.createBlockInTemplate` |

## What it catches

A call chain `->getLayout()->createBlock(...)` in a `.phtml` template, on any receiver. `magento-perf-check` analyzes templates automatically. In a project's own PHPStan setup, add `phtml` to `fileExtensions` to get this rule.

## Why it hurts performance

This is a Technical guidelines rule: templates must not instantiate objects. A block created in a template is not part of the layout structure. Layout XML cannot move, remove or configure it, and it is created again every time the template renders. The performance effect is indirect; the main problem is that the page structure is hidden in a template.

## Example

Bad:

```php
<?= $block->getLayout()->createBlock(\Acme\Promo\Block\Badge::class)->toHtml() ?>
```

Good: declare the block in layout XML as a child and render it by name:

```xml
<block class="Acme\Promo\Block\Badge" name="acme.promo.badge" template="Acme_Promo::badge.phtml"/>
```

```php
<?= $block->getChildHtml('acme.promo.badge') ?>
```

## How to suppress

Put the comment inside the same `<?= ?>` tag, on the same line; a comment in a separate `<?php ?>` tag on the line before does not apply to template output:

```php
<?= $block->getLayout()->createBlock(Badge::class)->toHtml() /* @phpstan-ignore magentoPerf.createBlockInTemplate (third-party template) */ ?>
```

## Known false positives

None known. `$this->helper()` and ObjectManager use in templates are covered by magento-coding-standard, not by this rule.

## Basis

| Source | Level | What it confirms |
|---|---|---|
| [Adobe: Technical guidelines](https://developer.adobe.com/commerce/php/coding-standards/technical-guidelines) | A | Section 6.2.6: "Templates MUST NOT instantiate objects. All objects MUST be passed from the Block objects." |

The SPEC's earlier claim that such a block "is not cached separately" has no source and is not used (see the [source audit](../source-audit.md)).
