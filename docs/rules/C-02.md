# C-02: Merge JavaScript Files switched on in `app/etc/config.php`

| | |
|---|---|
| Severity | `warning` |
| Status | experimental, after [calibration round 14](https://github.com/SilinMykola/magento-perf-check/blob/main/docs/calibration/round-14.md): the public corpus has no such settings; 2 of 5 private stores have merging on, both findings correct and of small impact, too few for a decision |
| Analyzer | settings of `app/etc/config.php`, read from its tokens ([ADR 11](https://github.com/SilinMykola/magento-perf-check/blob/main/docs/adr/0011-settings-read-from-config-php.md)) |

## What it catches

`dev/js/merge_files` with a true value in the `system` section of `app/etc/config.php`: for the default scope (`system.default`), a website (`system.websites.<code>`) or a store view (`system.stores.<code>`). A value is true as PHP casts it to bool, which is how core reads the flag: `'1'`, `1` and `true` are on, `'0'`, `0`, `''`, `false` and `null` are off.

`app:config:dump` and `config:set --lock-config` write the setting there. A value in the `system` section of `config.php` wins over the database, and the file is usually in the repository, so it reaches every installation that does not override it in `app/etc/env.php` or with an environment variable.

The file is read whatever `--paths` says, because the setting applies to the whole store. Not seen: the same setting in `app/etc/env.php` or in the database, and a value that is not a literal, such as a constant.

## Why it hurts performance

Adobe does not recommend it: "We do not recommend enabling Merge JavaScript Files. This setting was designed only for synchronously-loaded JavaScript in the HEAD section of the page and can cause bundling and RequireJS logic to work incorrectly. It's kept for backward compatibility only and provides no performance benefit when HTTP/2 is enabled."

In core, the flag only changes the scripts that the page renderer prints in the head: each group of them becomes one merged file. Modules that RequireJS loads are not among them. On merging in general, Adobe adds: "HTTP/2 downloads static files asynchronously. Browsers must download an entire merged file before processing the file contents."

## Example

Bad, in `app/etc/config.php`:

```php
'system' => [
    'default' => [
        'dev' => [
            'js' => [
                'merge_files' => '1',
            ],
        ],
    ],
],
```

Good: set it to `'0'`, for example with `bin/magento config:set dev/js/merge_files 0 --lock-config`, or remove the key and leave the setting to the default, which is off.

## How to suppress

- **Command line:** Magento rewrites `app/etc/config.php` from the array it loaded and keeps only its own section comments, so no comment next to a value survives and none suppresses a finding. Set `C-02: enabled: false` in the [configuration file](https://github.com/SilinMykola/magento-perf-check/blob/main/docs/configuration.md#configuration-file), or keep the finding in a [baseline](https://github.com/SilinMykola/magento-perf-check/blob/main/README.md).
- **PHPStan:** this is not a PHP rule, so `@phpstan-ignore` does not apply.

## Known false positives

- The value is overridden where the tool does not look: Magento merges `app/etc/env.php` over `config.php`, and a `CONFIG__DEFAULT__DEV__JS__MERGE_FILES` environment variable replaces the value. A `config.php` that says `1` with an `env.php` that says `0` is reported, though merging is off. Set it to `0` in `config.php` as well, so the shared file says what runs.
- A store that needs merging for a reason Adobe does not cover, such as an old HTTP/1.1 server, still gets the finding: disable the rule.
