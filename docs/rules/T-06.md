# T-06: image without `width` and `height` in a storefront template

| | |
|---|---|
| Severity | `info` |
| Status | experimental, off by default: [calibration round 9](https://github.com/SilinMykola/magento-perf-check/blob/main/docs/calibration/round-9.md) found 87 % precision, but most correct findings are small icons and logos (impact share 19 %). Enable it with `enabled: true` in `magento-perf-check.neon` |
| Analyzer | PHPStan, identifier `magentoPerf.imageWithoutDimensions` |

## What it catches

An `<img>` without both a `width` and a `height` attribute, in a storefront template: a `.phtml` file under a module's `view/frontend` or `view/base`, or under a theme in `app/design/frontend`. Admin templates are left out. An attribute bound with Alpine.js, `:width` or `x-bind:width`, counts as set; a written one counts only when its value is a number or printed by PHP, so `width=""` and `height="auto"` are reported.

The rule also leaves out a tag in which PHP prints something outside the quoted attribute values, such as `<img src="..." <?= $block->getImageAttributes() ?>>`: that output may add both attributes. An `<img>` inside a `<template>` element, in an HTML comment or written as text inside a script is left out as well.

## Why it hurts performance

Without the size, the browser cannot reserve the image's space when it lays out the page. When the image arrives, the content below it moves down. This is layout shift, measured as Cumulative Layout Shift (CLS), one of the Core Web Vitals.

## Example

Bad:

```html
<img src="<?= $escaper->escapeUrl($bannerUrl) ?>" alt="">
```

Good:

```html
<img src="<?= $escaper->escapeUrl($bannerUrl) ?>" width="1200" height="400" alt="">
```

## How to suppress

The finding sits on an HTML line, where a `@phpstan-ignore` comment does not apply. Keep it in a [baseline](../baseline.md), or leave the rule disabled.

## Known false positives

- An image whose box CSS already fixes, for example with `style="height: 220px"` or `aspect-ratio`, so it cannot shift the page.
- A template that renders content for an email, such as the ones an email marketing module fetches to build a message: layout shift does not apply there.
- A template that only a module's own tests render, such as one under `view/frontend/templates/test`.
