# T-06: image without `width` and `height` in a storefront template

| | |
|---|---|
| Severity | `info` |
| Status | experimental, off by default: [calibration round 9](https://github.com/SilinMykola/magento-perf-check/blob/main/docs/calibration/round-9.md) found 77 % precision after a re-check, counting as false three images that the rule now leaves out, and most correct findings are small icons and logos (impact share 22 %). Enable it with `enabled: true` in `magento-perf-check.neon` |
| Analyzer | PHPStan, identifier `magentoPerf.imageWithoutDimensions` |

## What it catches

An `<img>` without both a `width` and a `height` attribute, in a storefront template: a `.phtml` file under a module's `view/frontend` or `view/base`, or under a theme in `app/design/frontend`. Admin templates are left out. An attribute bound with Alpine.js, `:width` or `x-bind:width`, counts as set; a written one counts only when its value is a number or printed by PHP, so `width=""` and `height="auto"` are reported.

The rule also leaves out a tag in which PHP prints something outside the quoted attribute values, such as `<img src="..." <?= $block->getImageAttributes() ?>>`: that output may add both attributes. An `<img>` inside a `<template>` element, in an HTML comment or written as text inside a script is left out as well. So is an image whose box CSS fixes: its `style` attribute, a rule in a `<style>` element of the same template, or a rule in a CSS or LESS file under `web/css` of the template's module (`view/frontend` and `view/base`) or of the theme and its module folder, whose selector ends in classes the image has (`.faq img.group-image`), sets a height in a length unit together with a width or an `aspect-ratio`, or a width (a length or a percentage) with an `aspect-ratio`. A `width` or `height` attribute counts as well; then the rules are applied in order, the stylesheets first and the template's `<style>` after them, also those for every `img`, then the `style` attribute, so a later `height: auto` undoes an earlier size. A rule inside an at-rule such as `@media`, in a `<style media="print">`, or with a pseudo-class, an id or an attribute anywhere in its selector, as in `a:hover img`, does not count; `!important` and specificity are not followed, nor are the ancestors in a selector of the template's own `<style>`. A rule of a stylesheet counts only when the elements its selector names before the image, such as `.card` in `.card img.avatar`, are around the image in the template, which the template must open and close evenly; the content of a `<template>` element is not counted. LESS nesting is followed (`.card { img.avatar { ... } }`, `&`), and a guard such as `& when (@media-common = true)` is read as always true; variables, mixins and `.min.css` files are not read. Whether a layout loads a CSS file, or the theme compiles a LESS file (a Hyvä theme does not), is not checked.

## Why it hurts performance

Without the size, the browser cannot reserve the image's space when it lays out the page. When the image arrives, the content below it moves down. This is layout shift, measured as Cumulative Layout Shift (CLS), one of the Core Web Vitals.

## Example

Bad:

```html
<img src="<?= $escaper->escapeUrl($bannerUrl) ?>" alt="">
```

Good:

```html
<img src="<?= $escaper->escapeUrl($bannerUrl) ?>" width="1200" height="400" alt="">
```

## How to suppress

The finding sits on an HTML line, where a `@phpstan-ignore` comment does not apply. Keep it in a [baseline](../baseline.md), or leave the rule disabled.

## Known false positives

- An image whose box a utility class fixes, such as Tailwind's `w-24 h-24`, or a stylesheet of another module or a parent theme: the rule reads the template and the stylesheets of its own module or theme.
- A template that renders content for an email, such as the ones an email marketing module fetches to build a message: layout shift does not apply there.
- A template that only a module's own tests render, such as one under `view/frontend/templates/test`.

## Known false negatives

- A rule in a module stylesheet that no layout loads, or in a LESS file that the store's theme does not compile, still counts: the image may shift although the rule stays quiet.
- The combinators `>`, `+` and `~` are read as "inside": `.a > img` and `.a + img` count for any image inside `.a`.
- PHP branches are read as one page: when an `if` opens `<div class="a">` and its `else` opens `<div class="b">`, each closed in its branch, an image in the `.b` branch counts as inside `.a` too.
