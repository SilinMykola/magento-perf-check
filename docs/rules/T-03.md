# T-03: JavaScript function declared once per item in a template

| | |
|---|---|
| Severity | `warning` |
| Status | experimental, off by default: no calibration yet, and its sources are theme code, not Adobe documentation. Enable it with `enabled: true` in `magento-perf-check.neon` |
| Analyzer | PHPStan, identifier `magentoPerf.repeatedScriptFunction` |

## What it catches

A named JavaScript function, `function name(`, declared inside a `<script>` in a part of a template that is rendered once per item:

- inside a PHP `foreach`, `for`, `while` or `do` loop of the template;
- anywhere in `templates/product/list/item.phtml`, which Hyvä renders once for each product of a list.

A name built with PHP output, such as `function initPriceBox_<?= $uniqueId ?>(`, is left out: each item then gets its own function by design. Anonymous functions are left out too.

## Why it hurts performance

Every item sends the same function again, and the browser parses it again and replaces the global function. On a product list of 36 items, a 5 KB function adds about 180 KB of uncompressed HTML. The Hyvä default theme renders the list JavaScript, such as `initWishlist()`, in separate blocks that are rendered once per list.

## Example

Bad, in `Magento_Catalog/templates/product/list/item.phtml`:

```html
<script>
    function initWishlist() { /* ... */ }
</script>
```

Good: declare the function in a template rendered once per page, such as `product/list/js/wishlist.phtml`, and call it from each item.

## How to suppress

The finding sits on an HTML line, where a `@phpstan-ignore` comment does not apply. Keep it in a [baseline](../baseline.md), or leave the rule disabled.

## Known false positives

- A loop that runs once, or a list template that a project renders once per page under the `item.phtml` name.
