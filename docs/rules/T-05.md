# T-05: external script without `async` or `defer` in a storefront template

| | |
|---|---|
| Severity | `warning` |
| Status | default set, after [calibration round 9](https://github.com/SilinMykola/magento-perf-check/blob/main/docs/calibration/round-9.md): 18 findings, all correct, 13 of them on pages that matter |
| Analyzer | PHPStan, identifier `magentoPerf.syncExternalScript` |

## What it catches

A `<script>` with a `src` attribute and without `async`, `defer` or `type="module"`, in a storefront template: a `.phtml` file under a module's `view/frontend` or `view/base`, or under a theme in `app/design/frontend`. Admin templates are left out.

The rule also leaves out:
- a script whose `type` is not a JavaScript MIME type of the HTML standard, such as `type="text/x-magento-template"`, or whose `type` is bound with Alpine.js or printed by PHP;
- a tag in an HTML comment, or written as text inside another script, such as `document.write('<script src=...>')`;
- a tag in which PHP prints something outside the quoted attribute values, such as `<script <?= $attributes ?> src="...">`: that output may add `defer`;
- a script inside a `<template>` element, nested ones included, which the browser does not run until a script copies it into the page.

A `src` built with PHP, such as `src="<?= $escaper->escapeUrl($url) ?>"`, is reported.

## Why it hurts performance

A `<script src>` without `async` or `defer` blocks rendering: the browser downloads and runs it before it goes on with the page. Hyvä's Core Web Vitals page says that every such script delays the Largest Contentful Paint, and that scripts not needed for the first render should use `defer` or `async`.

## Example

Bad:

```html
<script src="https://widget.example.com/reviews.js"></script>
```

Good:

```html
<script defer src="https://widget.example.com/reviews.js"></script>
```

The Hyvä page on loading external JavaScript describes another way: "the basic idea of all the above approaches is to load the script programmatically when needed."

## How to suppress

The finding sits on an HTML line, where a `@phpstan-ignore` comment does not apply. Keep it in a [baseline](../baseline.md), or leave the rule disabled.

## Known false positives

- A script that must run before the rest of the page, such as a consent manager that has to block other scripts, or a payment SDK whose documentation asks for a synchronous load. Keep it in the baseline.
- A script that the template prints only on a page where the delay does not matter.
