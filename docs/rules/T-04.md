# T-04: result of `$viewModels->require()` never used in a template

| | |
|---|---|
| Severity | `warning` |
| Status | experimental, off by default: no calibration yet, and its sources are theme code, not Adobe documentation. Enable it with `enabled: true` in `magento-perf-check.neon` |
| Analyzer | PHPStan, identifier `magentoPerf.unusedViewModel` |

## What it catches

A template that assigns what Hyvä's `$viewModels->require()` returns, or a call made on it, to a variable it never reads.

## Why it hurts performance

The call still runs: `$viewModels->require(Navigation::class)->getNavigation(4)` builds the category tree even when the template prints something else. `require()` also passes the view model to Hyvä's cache tag collector, so a view model that implements `IdentityInterface` adds its tags to the page, and the page is then purged when any of those entities changes, although it does not show them.

## Example

Bad:

```php
<?php $menuItems = $viewModels->require(Navigation::class)->getNavigation(4); ?>
<?= $block->getChildHtml('header-menu-cms') ?>
```

Good: remove the unused call.

## How to suppress

```php
// @phpstan-ignore magentoPerf.unusedViewModel (reason)
```

## Known false positives

- A view model required only for its cache tags on purpose. Say so in a suppression with a reason.
