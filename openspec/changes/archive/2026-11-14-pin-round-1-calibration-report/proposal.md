# Proposal

## Why

`docs/calibration.md` is generated by `bin/calibration/report` and records round 1. The script took the rules of the current default set with their current severities, so after later rounds moved rules in and out of the default set and lowered severities, regenerating the page rewrote round 1: rules that left the default set disappeared, rules added later showed up as "no findings", and decisions were recomputed against severities that round 1 had already lowered (P-DI-01 read "downgraded to info" instead of "to warning"). The page could no longer be regenerated, so a corpus line had to be added to it by hand.

## What Changes

- The script keeps the default set of round 1 and each rule's severity at that round in a fixed list, and reads the graded samples for those rules only. `--check` reports a top-level grading file of any other rule: later rounds grade in `graded/round-N/`.
- The runs table keeps the two runs round 1 was sampled from, instead of reading `docs/calibration/runs/`, which a repeated run rewrites.
- `report --print` prints the page instead of writing it, and a unit test compares that output with the committed `docs/calibration.md`.
